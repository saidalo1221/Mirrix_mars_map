# Elevation methodology

## Additional archive terrain

**Search HiRISE terrain** reads the paginated USGS HiRISE DTM catalog and matches catalog descriptions and product IDs in the browser. Selecting a result retrieves its current asset URL from the item metadata and checks several sites near the center for a usable routing window. Results that fail projection, coverage, or connectivity checks display an error.

**Find routing terrain** queries the NASA/USGS controlled HiRISE and CTX STAC collections near the selected point. It considers up to 12 results per collection and reads a bounded GeoTIFF window in a Web Worker using HTTP range requests. For CTX it uses the areoid-adjusted DEM asset. The importer requires a north-up Mars equirectangular grid in meters, suitable sample spacing (at most 30 m), valid elevation at the selected point, and at least 70% finite cells in the window. It also verifies a connected example route under a 15° grid slope ceiling. The app uses a built-in overview up to 12 m spacing where available. Native coarser grids remain at native spacing. It preserves no-data and honors the reported scale and offset.

The app rejects incompatible models, including polar projections, and checks only local windows. Passing these checks establishes that the model can support the app's graph search. Stereo artifacts and hazards below the grid spacing still require independent review. Archive regions are loaded on demand and retained for the current session. Mawrth Vallis and Gusev have bundled HiRISE windows sampled at about 8.1 m using source overviews. The Gusev preset coordinates were selected inside the Spirit landing-site DTM footprint. The sample walk is hypothetical. Run `node scripts/bundle-archive-terrain.mjs` to regenerate the two windows. [USGS HiRISE documentation](https://stac.astrogeology.usgs.gov/docs/data/mars/hirise_dtms/), [USGS CTX documentation](https://stac.astrogeology.usgs.gov/docs/data/mars/ctxdtms/)

The global 4 pixels-per-degree NASA MOLA grid is 1,440 × 720 at 0.25° spacing, about 14.8 km at the equator. It preserves the native signed meter values and their GMM3 Mars areoid vertical reference. Preprocessing changes column order to support east-positive signed longitudes. Source elevations include interpolation where MOLA coverage left empty bins. [PDS MEGDR label](https://pds-geosciences.wustl.edu/mgs/mgs-m-mola-5-megdr-l3-v1/mgsl_300x/meg004/megt90n000cb.lbl)

The Jezero grid uses a bounded subset of the CTX stereo mosaic, sampled at native 20 m projected pixel spacing. Its bounds describe sample centers, with rows running north to south. The source equirectangular projection uses a 3,396,190 m Mars sphere and an 18.4663°N standard parallel. Preprocessing inverts that projection to get planetocentric latitude and east-positive longitude and rounds serialized heights to 0.01 m. The datum is MOLA-aligned topography. [USGS CTX GeoTIFF](https://planetarymaps.usgs.gov/mosaic/mars2020_trn/CTX/ScienceInvestigationMaps_JPL/M20_JezeroCrater_CTXDEM_20m.tif)

The Gale Pahrump Hills raster samples every tenth row and column of the nominal 1.01 m HiRISE stereo DTM. Effective analysis spacing is approximately 10.1 m. The subset uses the Mars 2000 equipotential surface reference. [HiRISE DTM and metadata](https://www.uahirise.org/dtm/dtm.php?ID=ESP_040770_1755)

The inspector uses bilinear interpolation and reports the underlying product. Null cells invalidate interpolation when they have positive weight. When a regional value is unavailable, the inspector can show global MOLA. Longitude wraps across the MOLA seam and polar queries use the outermost latitude row. Routing uses native grid-center heights and does not use the global fallback.

Regional ground distances vary with latitude and direction. Distance computations use a 3,389,500 m mean-radius Mars sphere. The reference radius for this distance approximation differs from the source projection radius used to decode the GeoTIFF. Compare heights across products only with awareness of datum, sampling, and registration differences.
